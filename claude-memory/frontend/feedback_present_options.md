name: feedback_present_options
description: Felix wants multiple options with tradeoffs presented before decisions, not a single proposed approach
type: feedback
---

When a decision point has meaningful tradeoffs, present 2-3 concrete options with pros/cons instead of proposing just one approach and asking for confirmation.

**Why:** During autoresearch skill design (2026-03-26), Felix rejected a SKILL.md draft because it proposed a single validation approach. He wanted "several possibilities what might be chosen for validation and push some ideas back first to decide upon." Same pattern appeared when designing measurement strategy — he didn't want to be handed a metric command, he wanted to see options and choose.

**How to apply:** At design/setup phases where there are legitimate alternatives (not trivial choices), lay out the options concisely with tradeoffs. Applies to: skill/workflow design, architecture decisions, measurement strategies, validation approaches. Don't overdo it for obvious or low-stakes choices.
