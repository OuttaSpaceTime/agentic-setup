**2026-07-01 — admin-expiry-item UI bug fix (worktree 592, same branch as this file, already had the ported architecture from the 591 port above).** Felix reported: membership cards render crushed to near-zero height and the load-more spinner is visible from initial render (screenshot: dozens of hairline cards). Root cause: `MembershipCardComponent`'s `:host { display: contents }` means its host element establishes no box — the real flex item inside `.inbox-entries` (a `flex-direction:column; overflow:auto` container) is the inner `<ui-card>` element. The existing CSS rule `.inbox-entries > app-membership-card { flex-shrink: 0 }` targeted the display:contents host and was a **complete no-op** (Angular's `>` combinator still matches the DOM structurally, but the rule does nothing because the "box" it'd apply to doesn't exist). `ui-card` thus kept the flexbox default `flex-shrink:1`, and because the parent has `overflow:auto` (which makes the browser use `0` instead of content-based min-size for automatic sizing), every card crushed down to fit instead of the container scrolling — the classic "flex-shrink + overflow:auto on `display:contents` child" trap. Confirmed via a `getComputedStyle(uiCardEl).flexShrink` test (no prior art for CSS-computed-style specs in this codebase, but it's the precise, non-flaky way to test this class of bug — layout/height assertions would be flakier). Fix: moved `flex-shrink: 0` into `membership-card.component.css` targeting `ui-card` directly (the component's own real box), removed the dead rule from `admin-expiry-item.component.css`. The "spinner visible on initial load" symptom was NOT a separate bug — it was a downstream effect of crushed cards never filling the viewport, so the infinite-scroll sentinel never left view and kept auto-firing `loadMore`. **General lesson: any `display:contents` component reused inside a `flex + overflow:auto` list needs `flex-shrink:0` baked into its OWN stylesheet (on its real root element), not into the consumer's stylesheet targeting the wrapper tag** — same trap would hit `notification-card`, `component-card`, `monitoring-list-card`, etc. (all `display:contents`, per grep) if ever reused inside a similar scrollable flex list.
