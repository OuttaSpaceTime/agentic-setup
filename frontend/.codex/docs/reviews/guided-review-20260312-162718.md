## Checkpoint 3/6: Expiry Flow

- Expiry editing is now keyed off the viewed membership’s role.
- Invite-only permissions no longer unlock expiry editing.
- Expiry-only users can still access the page and edit only the memberships they are allowed to expire.

### Code Walkthrough

- body excerpt:

```ts
get canEditMembership() {
  return (
    typeof this.expiryPermission === 'string' &&
    this.currentSessionService.currentSession.hasPermission(
      this.expiryPermission,
    )
  )
}
```

- interpretation:
  - This is the key behavioral fix. The old aggregate membership-write check is gone from the edit path.
- review questions:
  - Is there any path left where expiry editability is still inferred from “can write memberships” rather than “can expire this membership role”?
  - Do you expect any memberships without a role to render here?
