## Detailed Findings (Ordered by Severity)

### F1 - Blocking: `appShowForPermission` does not react to session updates
- File reference: `src/app/shared/directives/permissions/has-permission/has-permission.directive.ts:29`, `src/app/core/auth/services/authentication/current-session.service.ts:13`, `src/app/core/interceptors/refresh-session.interceptor.ts:14`
- Issue: The directive only re-renders in `ngOnInit`/`ngOnChanges`; static permission inputs (string literals/constant arrays) do not trigger `ngOnChanges` when session permissions change.
- Impact: Permission-gated elements can remain incorrectly shown/hidden after `CurrentSessionService.setCurrentSession(...)` updates, producing stale authorization UI.
- Suggested fix: Make directive reactive to session changes (e.g., expose a read-only session observable from `CurrentSessionService`, subscribe with `takeUntilDestroyed`, call `render()` on each session emission). Add a directive test that updates session after first detect cycle and expects DOM to update.

### F2 - Medium: Subscriber-deletion contract is inconsistent with authoritative-role rule
- File reference: `src/app/features/monitoring-lists/components/tabs/subscribers/subscribers-tab.component.ts:164`, `src/app/features/monitoring-lists/services/subscriptions.service.ts:46`, `src/app/features/monitoring-lists/services/monitoring-list-authorization.service.ts:75`
- Issue: If post-mutation role is the intended source of truth, current runtime behavior is acceptable, but surrounding artifacts still imply old behavior (redirect expectation and ownership-loss wording). The branch at `requestDeletion` is likely effectively dead under the new rule.
- Impact: Future maintainers may misinterpret intended UX; tests and UI copy can drift from product behavior.
- Suggested fix: Encode the rule explicitly by removing/rewriting obsolete redirect branch and updating tests/text to state that post-delete behavior is decided by the new role.

### F3 - Non-blocking: Lint policy guardrails were relaxed in an unrelated change
- File reference: `.eslintrc.json:23`
- Issue: `no-restricted-syntax` entries for `effect/input/signal/computed` were removed while implementing permission refactor.
- Impact: This broadens permitted architectural patterns unexpectedly and can drift from established repository constraints.
- Suggested fix: Confirm intent. If accidental, restore removed entries in a dedicated commit or explain policy update in PR description.
