## Why No Finding Was Raised

- Invite affordances are consistently scoped to `MEMBERSHIP_INVITE_PERMISSIONS` at the page entrypoint and to per-role invite permissions inside the form.
- Expiry affordances are consistently scoped to a single resolved `expire:org:membership:role:*` permission in both the template gate and the imperative edit check.
- The shared permission directive contract still matches the new call sites.
- Targeted specs cover the important split cases:
  - expiry-only session cannot see the invite button
  - invite-only session cannot edit expiry
  - expiry permission must match the viewed membership role
  - invite options narrow to the roles the session can actually invite

## Architecture and Style Gates

- `aligned`: action-specific permission checks now sit at the UI seam that actually performs the action.
- `aligned`: route/sidebar still use the broader write-capability set, preserving existing access semantics for expiry-only users.
- `aligned`: tests follow nearby Angular/Jasmine style and exercise permission state through `CurrentSessionService` rather than bypassing runtime checks.
- Complexity: `acceptable complexity`

## Residual Risks and Questions

- `InviteFormComponent.selectItems` is computed from `currentSessionService.currentSession` at component instantiation, not reactively from `currentSession$`. That is acceptable for the current modal lifecycle, but if permissions ever become mutable while the modal stays mounted, the dropdown would not refresh automatically.
- This review was intentionally scoped to the permission split. Role-label wording and announcement readiness were not treated as review blockers here.

## Strengths

- The expiry path uses the same resolved permission for both render-time and click-time authorization, which prevents drift between visible and executable behavior.
- The implementation reuses the shared permission directive instead of inventing component-local authorization semantics.
- The specs verify behavior from realistic permission sets rather than only checking helper functions in isolation.
