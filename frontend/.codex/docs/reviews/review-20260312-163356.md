## Findings

### 1. Redundant custom pipe expands the change surface without adding domain value

- Severity: medium
- Evidence:
  - `src/app/shared/pipes/membership-role-label.pipe.ts:1`
  - `src/app/core/layout/components/menu-avatar/menu-avatar.component.ts:12`
  - `src/app/features/consumption-reports/components/billing-memberships-table/billing-memberships-table.component.ts:5`
  - `src/app/features/monitoring-lists/components/tabs/subscribers/components/subscription-modal/subscription-form/subscription-form.component.ts:38`
- Why it matters:
  - The new `MembershipRoleLabelPipe` is just a thin wrapper around `membershipRoleLabel(...)`, but introducing it forces several standalone components to replace a built-in Angular pipe import with a repo-specific pipe import.
  - That increases the size of the diff and the amount of framework plumbing for what is effectively a single string-formatting concern.
  - It also moves the implementation away from the direction you just set: keep using `TitleCasePipe` unless there is real domain behavior that belongs on a model.
- Suggested direction:
  - Remove the custom pipe.
  - Either keep `titlecase` at display sites, or expose a real model getter where the output is intentionally not title-cased.

### 2. `membership-role.ts` became a shared behavior hub instead of pushing behavior onto the domain model

- Severity: medium
- Evidence:
  - `src/app/features/memberships/types/membership-role.ts:12`
  - `src/app/features/memberships/types/membership-role.ts:19`
  - `src/app/features/memberships/types/membership-role.ts:47`
  - `src/app/features/memberships/types/membership-role.ts:55`
  - `src/app/features/memberships/types/membership-role.ts:61`
  - `src/app/features/memberships/components/membership-card/membership-card.component.ts:63`
  - `src/app/features/monitoring-lists/components/tabs/subscribers/components/subscriber-card/subscriber-card.component.ts:80`
  - `src/app/core/auth/models/session/session.model.ts:73`
- Why it matters:
  - The new `MembershipRoleDefinition` list now owns labels and permission mapping, while the actual consumers still have to import helpers or add adapter getters to reach that data.
  - That leaves the behavior outside the models and spreads knowledge of the helper module across `Session`, membership cards, subscriber cards, billing tables, and templates.
  - The result is extra indirection without actually simplifying the call sites.
- Suggested direction:
  - Keep the role union constants if needed, but move label/permission derivation onto the model layer that owns the role value.
  - At minimum, `Membership` should expose role label / invite permission / expiry permission accessors directly if that is the intended abstraction point.

### 3. `CardTitleComponent` was widened only to work around the new label helper path

- Severity: low
- Evidence:
  - `src/app/shared/components/card-title/card-title.component.ts:19`
  - `src/app/shared/components/card-title/card-title.component.html:10`
  - `src/app/features/memberships/components/membership-card/membership-card.component.html:11`
  - `src/app/features/monitoring-lists/components/tabs/subscribers/components/subscriber-card/subscriber-card.component.html:12`
- Why it matters:
  - `CardTitleComponent` previously had one simple rendering rule for `titleDetail`.
  - The new `titleDetailTitleCase` input exists only because upstream code now passes preformatted labels from helper getters.
  - That makes a shared UI primitive more complex to compensate for a design choice made elsewhere.
- Suggested direction:
  - If role details should still be title-cased, revert these call sites to the raw role string and keep `CardTitleComponent` simple.
  - If they should not be title-cased, expose that as a model-level string and consider whether `CardTitleComponent` should really own casing behavior at all.

## Summary

I did not find a runtime bug in this narrowed area, but I do think the current abstraction direction is off: the custom pipe, the shared role-definition object hub, and the `CardTitleComponent` escape hatch all add indirection around a problem that would be cleaner either with the existing `titlecase` pipe or with a small model-level API.
